- Risks found:
  - **Expiry is lazy.** A student who closes the tab is ended only when their next call, a faculty list/detail/export call, or `sweep_expired()` runs. The T5 worker must call `sweep_expired()`; faculty GETs therefore write.
  - **Lease vs slow chains:** lease is 60 s; a provider chain with retries/backoff can run longer. If it does, a second worker may also process the same stored answer; the PK `(session_id, idx)` makes the loser fail and its retry replays the winner's reply (safe, wasteful). Not triggered in any test.
  - **Lockout is a denial-of-service lever:** anyone who knows a classmate's ID can lock that student out for 15 min with 5 wrong codes (faculty `reset-code` clears it). Parameters are env-set (D16).
  - `rescore` keeps the old `scores` rows; T5 must replace the runs, or the median mixes old and new.
  - `Interviewer.restore` mirrors the action names in `interviewer.py`/`policy.py`; renaming one silently breaks rebuild. `test_restore` is the guard, so keep it in the fast suite.
  - Model recorded on an AI turn is whichever served the last call in that reply; if classification used model A and phrasing fell back to canned text, `model` says A and `meta.llm_degraded` says the text was canned.
  - Bank list is ordered by question id, not upload order. The sample bank (5 concept, 2 applied) is too small: any full-length viva exhausts it and falls back to 3 canned prompts, which would flag every real session `question bank exhausted`. The demo uses slower pacing to avoid that.
  - Two bugs I found in my own tests, not the code: a tamper test that was a no-op 1 time in 16 (flaky, fixed), and an assumption that the bank list comes back in upload order (it is id order). `mimetypes` returned `audio/x-wav` here, so audio types are pinned in code.
