### Item 2: real Ollama, stacks A and B (plus E and F), 34 turns each, both sequential LLM calls measured
End to end, "student stops" -> first AI audio chunk, real backend `POST .../answer`, Ollama `llama3.2:3b` (warm), Piper alba. p50 / p95 in seconds (`summary.csv`, area `e2e_real_ollama`):

| B | faster-whisper small, CPU | 2.46 / 3.79 | 2.30 / 3.12 | 2.30 / 3.23 | 1.99 / 2.92 |

- **LLM calls, real (as shipped = non-streaming adapter):** classify p50 0.41 s / p95 0.56 s (31 calls, stack A; 0.40 / 0.54 s, 32 calls, stack E); phrase p50 1.05 s / p95 1.62 s (7 calls, A; 1.03 / 1.28 s, 9 calls, E). The engine made 1.12-1.21 calls per turn (the simulated run assumed 1.41); 2-3 of 34 turns needed no call (the opener's first answer only changes phase).
- **First-token latency (streaming replay, local):** classify first token p50 0.05 s (p95 0.06 s), total 0.22 s; phrase first token p50 0.05 s, **end of first sentence p50 0.48-0.56 s (p95 0.67-0.70 s)**, end of reply p50 0.77-0.86 s. **Bias:** each replay sends the identical prompt right after the real call, so Ollama's prompt cache is warm: these are lower bounds, and part of the gap to "as shipped" is caching, not streaming.
- **Parallel classify+phrase is not a lever on one local model.** p50 is unchanged (most turns have no phrase call) and p95 gets *worse* than sequential streaming (A 2.33 vs 2.14, E 2.24 vs 1.99, F 3.28 vs 2.57): both requests compete for the same GPU. It may still help on a cloud provider; that measurement waits for the merge.
- Everything shares one M2 (STT, Ollama, TTS, VAD, API): Piper's first chunk was 0.13-0.15 s p50 here versus 0.07-0.08 s when it ran alone in T3.

### Item 5: long answers (real clips joined with 0.5 s of silence; 22.8 / 44.9 / 67.6 / 94.1 s)
Decode time, median of 3 (`stt_long_answers.csv`): faster-whisper base 0.53 / 1.04 / 1.43 / 2.00 s; small 1.73 / 3.38 / 5.09 / **6.84 s**; whisper.cpp base 0.39 / 0.72 / 1.05 / 1.33 s; whisper.cpp small 0.92 / 1.82 / 2.61 / 3.45 s. ### Item 7: does Plan B trip, and is p95 < 2.5 s reachable? (real local LLM)
- **Plan B (E2E p95 > 4 s) does not trip.** The slowest real stack (B, small on CPU) is 3.79 s as shipped; the best (E) is 2.78 s.
- **p95 < 2.5 s is reachable, with two levers:** (1) start TTS at the first sentence of the phrase instead of waiting for the whole reply (E 2.78 -> 1.99, A 3.09 -> 2.14), and (2) a base-size STT (whisper.cpp or faster-whisper). With small STT it is borderline (F 2.57). Speculative STT start lowers p50 by about 0.2-0.3 s (E 1.23 -> 1.01) and does little for p95. As shipped (no streaming), no stack meets 2.5 s at p95. The cost of base STT is real-voice accuracy (term recall 0.87-0.89 vs 0.96-0.98 for small). Cloud LLM figures: pending.
