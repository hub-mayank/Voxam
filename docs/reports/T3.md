- Risks found:
  - **Licences:** `piper-tts` is **GPL-3.0-or-later**. The `lessac` voice's data licence (Blizzard 2013) I could not read, so its product use is unverified; `alba` is CC BY 4.0. macOS voices are Mac-only and their terms are unchecked.
  - Indian-English output: only macOS `say` has en_IN voices; Piper and Kokoro do not. A server on Linux cannot use `say`.
  - The interviewer makes two sequential LLM calls per answer (classify, then phrase). With a 0.4 s first-token assumption that is 0.93 s p50 of the E2E; it is the second-largest term after endpointing + STT.
  - Python 3.14: LiveKit's `AudioSource` raises "no current event loop" when built outside a running loop (works inside one). Pipecat deprecated `PipelineRunner` in 1.3 (now 1.12), so most examples are stale. Pipecat's default stop timeout (0.8 s) split a test clip at a pause into two turns.
  - The WebSocket proof has **no authentication** (browsers cannot set headers on a WebSocket: the session token must go in the first message or a subprotocol) and TCP head-of-line blocking on bad networks is untested. Browser echo cancellation (`getUserMedia` constraints) is needed for barge-in on speakers. `uvicorn` needs the `websockets` package to serve WebSockets and `backend/requirements.txt` does not have it.
  - The speculative-STT and parallel-LLM figures are computed from measured parts, not implemented systems.
  - My own bugs found by testing: the first barge-in test failed because the server only considered itself "speaking" while synthesising (milliseconds) instead of while the client was still playing; fixed by tracking the playback window.
