# T4 / V3 hands-free voice (Silero VAD, pre-roll, barge-in guard): ⚠️ partial   (2026-10-13, VOICE)
Hands-free mode now uses the real voice-activity detector and works end to end with real STT/TTS on synthetic speech. **Reply streaming into TTS (the biggest latency lever) is not done**, and nothing has been run with a real microphone. Branch `task/T4-v3-handsfree`.

- Changed: `backend/app/voice/vad.py` (`SileroVad` with start/hangover rules, `reset`, adjustable start threshold; `make_vad` with a loudness fallback when `pysilero-vad` is missing), `session.py` (pre-roll buffer so the answer starts before the detector was sure; barge-in needs ~320 ms of speech while the AI is playing; the VAD is reset between answers), `config.py` (`VOICE_VAD`, `VOICE_HANGOVER_MS`, `VOICE_PREROLL_MS`), `requirements.txt` (`pysilero-vad`, MIT, in CREDITS), `scripts/voice_bot.py` (references, whole-stream word error rate), voice lab hands-free option (`?mode=hands_free`, "I'm done" button), docs.
- Evidence: `python -m pytest -q --ignore=backend/tests/test_voice_spike.py` -> **467 passed, 2 skipped**; `npm run check` -> 38 passed, 3 opt-in skipped. New tests: Silero rules with an injected probability function (start needs 96 ms, end needs 19 quiet chunks, a short blip never starts, a 256 ms pause inside an answer is bridged, frames of any size are buffered, reset); the session keeps the lead-in (answer starts at 0 ms with 300 ms quiet before the speech); a 100 ms noise during AI playback is not a barge-in but 400 ms of speech is; and a **real-model** test (Piper speech in 20 ms frames: one `speech_start` near 1 s and one `speech_end` about one hangover after the last word).
- **End to end, hands-free, real whisper.cpp + Piper + Silero, mock LLM, 34 synthetic macOS-voice clips cycled to 40 answers** (`results/voice_handsfree_local_synth.csv`, `provider=live`, clean tree): **whole-stream word error rate 0.059**; per-answer median 0.042, 17 of 40 exact; server latency (end of speech detected -> first AI audio) p50 0.40 s, p95 0.60 s, so the student waits about 0.6 s hangover + 0.4-0.6 s with a canned reply.
  - One clip (`t23`, recorded with a deliberate pause) was **cut into two answers** by the 600 ms hangover; the per-answer column is index-aligned and shifts after a split, which is why the stream figure is the one to quote. This is the known trade-off of the hangover.
  - The first run of the script (34 answers, before the stream figure existed) had the same single split and reads 0.067 over the stream (it dropped the last clip); not kept in `results/`.
- Not verified / not run: **a real microphone and real people** (accents, breath noise, room noise, echo from speakers); the browser hands-free path (the lab page supports it, untested in a browser); concurrency of many Silero detectors (one model per session; CPU at 100+ sessions is a T7 question); **reply streaming**; the LLM leg (mock here; V2b measured Groq separately: p95 3.04 s in push-to-talk).
- Risks found:
  - A thinking pause inside an answer longer than 600 ms ends it early. Raise `VOICE_HANGOVER_MS` (800-1000) if real students pause; the cost is latency.
  - Echo: with speakers, the AI's own voice can come back through the microphone. The 320 ms barge-in guard helps; headphones are still the real fix (and should be in the rules text).
  - `pysilero-vad` is a compiled wheel with its own model file; it installs on Python 3.14/macOS arm64 here; other platforms were not tried (the fallback detector logs a warning).
