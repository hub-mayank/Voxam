# Faculty screen map

This map records the separate card branches, not a merged application. On `feat/parth-pa-7`, the session list, bank/roster sections and export/release section are built. Login and the viva list remain placeholders on this branch (implemented on PA-1). Session detail and audio remain placeholders here (implemented on PA-3/PA-4). No routes were changed.

## Not done / blockers

- **PA-5 blocked:** the latest request requires a dimension-specific override. `OverrideRequest` only has `new_total` (0-100) and `reason` (3-2000 characters). There is no dimension selector field, per-dimension new score, or per-dimension override history contract. Mayank must either approve the existing total-only behavior or arrange a contract/type/wrapper change. Following the instruction to stop a card with a missing API capability, review-note and rescore controls were also not implemented. `feat/parth-pa-5` points to PA-4 and has no PA-5 commit.
- **Integration is pending:** PA-4 branches from PA-3; PA-6 branches from PA-2; PA-7 branches from PA-6. The PA-1 login/viva-list branch and PA-3/PA-4 detail/audio branch must be integrated by Mayank before one checkout contains the full workflow. No merges or pushes were performed.
- **Viva creation is still missing:** `POST /faculty/vivas` exists, but `faculty.ts` has no create-viva method. There is no create-viva UI. A fresh viva with no joined students is needed to verify successful bank upload/approval; the populated DEMO viva is already locked for those operations.
- **Reset-code UI is not built:** the typed `api.resetCode()` exists, but this run implemented the requested roster upload/copy flow only. If an upload succeeded but its response was lost, listing the roster cannot recover the plaintext code; the existing reset endpoint is needed.
- **No browser or seeded-backend proof yet:** real turn-5 playback, channel assignment, signed-link expiry/recovery, clipboard behavior, downloads, persistence after browser refresh, real 422 rows and real 401 redirects are not verified. Unit tests use mock APIs/media; they are not seeded-backend proof. The DEMO seed uses text sessions, so audio verification needs a recorded local voice session with non-null offsets.
- **Windows check limitation:** `npm run check` cannot complete because `frontend/scripts/check-schema.mjs` fails to launch `npx`. Typecheck, lint, test and build were run individually per the approved instructions; schema freshness was not run. No shared script was edited.
- **Scope difference from TEAM_PLAN:** the original PA-5 card calls for an override but does not demand dimension-level overrides; the latest request does. PA-6/PA-7 use collapsible sections on the existing per-viva page, not new routes. PA-6's single commit is 302 changed lines including tests, two above the plan's 300-line guideline; it stays within the requested card and owned files.
- **PA-3 inherited limitation:** a missing `scoring.total_spread` renders a blank value; it is required by the schema. This run did not alter that read-only score display.
