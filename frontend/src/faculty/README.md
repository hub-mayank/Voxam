# Faculty screen map

This document maps the faculty UI and distinguishes implemented behavior from API-contract-only operations and unverified backend behavior. The `feat/parth-pa-7` branch is PA-7 stacked on PA-6 and now includes canonical `main` at `87f4ab1d4b160f253f0ff786c10a743595700afb`, which contains PA-1 through PA-6. Bank, roster, and export/release controls are sections of the existing viva session list; no new routes were added for them.

| --- | --- | --- | --- |

## Status and limitations

- **PA-5 override scope:** PA-5 commit `560e27d74fd35761ecb401e5b55cb663417bbb93` (`PA-5: faculty review actions`) is included in canonical `main` and therefore in this merged branch. It implements total-only overrides, review notes, and rescore controls. Dimension-specific overrides remain unsupported by the available API contract, which accepts only `new_total` and `reason` and provides no dimension selector, per-dimension score, or dimension-specific override history.
- **Question-bank and roster navigation:** these controls are sections on the existing per-viva session-list page, not separate routes. New codes can be issued for students with no session or a rejoinable session; the API rejects resets after a session ends. Revocation blocks future joins/rejoins and preserves existing session access and records.
- **Seeded/backend proof:** unit tests use mocked APIs/media and do not establish real-backend behavior. The populated DEMO seed is locked for bank changes and contains text sessions; verify uploads on a fresh, unjoined viva and audio with a recorded local voice session. Signed-link expiry/recovery, real 422 row errors, real 401 redirects, clipboard behavior, CSV download, and visibility persistence against a seeded backend still need manual verification.
- **Counts:** `session_counts` includes only statuses present in the database and may be empty. Whether to display missing statuses as zero or omit them remains a product question; these are session statuses, not one overall viva status.
- **Seeded review screenshots:** `scripts/run_local.sh` creates LOCAL questions and roster entries without sample sessions, while `scripts/seed_demo.py` creates populated DEMO dashboard states. Choose the appropriate dataset for each review; use a fresh unjoined test viva for bank operations.
- **Endpoint notation:** API paths use `{viva_id}`; the API guide may abbreviate this as `{id}`, while browser routes use `:vivaId`. These identify the same viva. The route table maps the faculty API operations relevant to these screens; signed audio is obtained through `audio.url`.
